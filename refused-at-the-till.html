Refused at the till

What a store should say when it declines an automated session. The before is the modal an agent received on nike.com on 22 August 2026, recreated line for line (the screenshot is in the record). The after is the same moment, redesigned for two readers at once: the person who will be told about it, and the agent that will do the telling. Both are real HTML, and the tree beside each is what an agent reads, produced by the same reader used in the six runs.

The pattern

Name the real cause

If the refusal is for automation, say automation. A cause written for the common case (a coupon plugin) becomes a false statement the moment an agent relays it to a person. Truthful copy is the cheapest accountability there is.

State what did not happen

A refusal is a state change that did not occur. Say so: nothing was added, nothing was charged, the bag is what it was. An agent cannot infer this from "View Bag", and neither can a person in a hurry.

Point to the lane, or say there is none

Stores are allowed to refuse agents. They should say where agents are allowed instead: a product feed, a UCP endpoint, the Shop skill. If there is no lane, say that too. Silence reads as a bug; a stated policy reads as a decision.

This is a proposal, not a standard, and it is not Nike's design. It is one screen from the six runs, redesigned so that the same words serve the person and the agent, and so that the accessibility tree says exactly what the pixels say. Source for both modals is in before and after. Pattern 02, the variant picker, follows.
